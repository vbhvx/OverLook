How a signal reaches the map

  1. Fetches each source on its own schedule

    USGS every 2 minutes, OpenSky and Open-Meteo every 15, inside their published limits. Three failures in a row open that source's circuit.

  2. Stores each record once, then links it

    A SHA-256 hash decides insert, update or skip in PostGIS. Rules then list what lies within 100 km and 12 hours of an earthquake.

  3. Pushes the change to every open map

    The worker sends a Postgres NOTIFY. Each API replica relays it over Server-Sent Events, so browsers refresh without polling.

Keeps working when a source fails. Each guarantee has a test.

Stops calling a failing provider

After three failures the circuit opens for five minutes. One trial call then decides whether it closes.

Ingests once across many workers

A Postgres advisory lock picks one leader. If it crashes, a standby takes over within 10 seconds.

Questions

Setup, data sources and what a correlation means.

Read the documentation

Which layers are live?

Earthquakes, aircraft and weather. Vessels, satellite passes, cameras and infrastructure are curated samples, marked simulated on every record.

How do I run it?

Copy .env.example to .env and run docker compose up. The map opens on port 8080, with PostGIS, the API and the worker behind it.

Does a correlation mean one event caused another?

No. It records the distance and time between two signals, and its confidence stays at observational association.

What happens when a provider goes down?

Its runs are recorded as failed and its last records stay until they expire after 72 hours. The other providers carry on.

Can it run more than one worker?

Yes. Extra workers wait on a Postgres lock and take over if the leader stops.
